# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository Overview

An archive of an Arch Linux desktop setup. Nothing here is deployed. There is no installer: the `.dotbot` submodule,
`z-install.conf.yml`, `z-install-dots` and `link_conf.sh` were removed once every path they linked had moved to the
flake or to host-local state, or turned out to be dead, config for programs neither host installs.

The live configuration for songbird and tpnix is generated by Home Manager in the
[`Bad3r/nixos`](https://github.com/Bad3r/nixos) flake. Shell, editor, terminal, window manager, launcher and theming
come from there, and Home Manager writes its user units into `~/.config/systemd/user`.

Two rules follow from that:

- A file added here takes effect nowhere. New configuration belongs in the flake.
- Never point `~/.config/<app>` at this working tree. Home Manager writes real files and store symlinks at those
  paths, and a link back into a repository makes activation write into the repository instead.

## Submodules

- `.i3sass` - [`budlabs/i3ass`](https://github.com/budlabs/i3ass), i3 helper utilities that went with the archived
  i3 setup.
- `Mullvad-iOS-MacOS-DNS-Profiles` -
  [`mullvad/encrypted-dns-profiles`](https://github.com/mullvad/encrypted-dns-profiles). Still in use, and not
  archive material: the profiles provision encrypted DNS on iOS and macOS devices directly, independent of any host
  configuration here.

Fetch both with `git submodule update --init --recursive`.

## Layout

- `.local/bin/`, `.local/lib/`, `.local/share/` - Arch-era user scripts and a Font Awesome 6 drop. Most scripts call
  `pacman`, `yay`, `xdotool` or `wmctrl`, so they do not run on NixOS as written.
- `etc/` - system files for that machine. `etc/kernel/cmdline.d/*.conf` splits the kernel command line by category
  (graphics, performance, IPv6, storage, system) and `etc/kernel/install.d/85-cmdline-d.install` concatenates and
  deduplicates the fragments into `/etc/kernel/cmdline` during kernel install; `.local/bin/edit-kernel-params` and
  `.local/bin/verify-kernel-params` drive that scheme. The rest is Arch system configuration: pacman and its hooks,
  NetworkManager, `resolv.conf` and systemd-resolved, firewalld, Xorg, containers, sysctl, `locale.conf`, reflector,
  xfce4 helpers, and three systemd units. On NixOS the equivalents are `boot.kernelParams` and the matching flake
  modules.
- `usr/` - udev rules, tmpfiles drop-ins, a session desktop file and a few standalone scripts.
- `opt/kiro/` - a copy of the Kiro editor's `product.json`.
- `i3/`, `dunst/`, `x11/`, `themes/`, `ASCII/` - the pre-Home-Manager i3 config with its toggle scripts, the Arch
  `dunstrc` and its icons, `xinitrc`, `xprofile`, `Xmodmap` and `Xresources`, color schemes and terminal art. The
  live i3 setup is `modules/apps/i3wm/` in the flake; dunst and the GTK and Qt theming come from Stylix there.
- `misc/protonVPN-port-forwarding/` - a ProtonVPN port-forwarding service with its helper scripts and its own
  `CLAUDE.md`.
- `dockerfiles/`, `packages.txt` - a Fedora flatpak build image and the Arch package list.

## Working Here

```bash
# Signed commit, Conventional Commits subject
git add <files>
git commit -S -m "type(scope): description"

# Hooks: ripsecrets and typos, configured in .pre-commit-config.yaml
pre-commit run --all-files
```

`.typos.toml` holds the word and path exceptions for the typos hook.

Recommended commit types: `feat`, `fix`, `chore`, `refactor`, `docs`.
